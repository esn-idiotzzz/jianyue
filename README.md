# 简阅 1.3.1

简阅是 Android 漫画阅读应用，提供本地书架、JM 漫画入口、中文图源搜索与浏览、下载和阅读历史。阅读器和图源运行框架基于 Mihon，JM 接口与图片还原参考 JMComic-Crawler-Python，内置扩展来自 Keiyoushi；各项目的来源、用途和许可证见下方说明。

- 项目：[esn-idiotzzz/jianyue](https://github.com/esn-idiotzzz/jianyue)
- 下载：[最新正式版](https://github.com/esn-idiotzzz/jianyue/releases/latest)
- 系统：Android 8.0 及以上，`arm64-v8a`
- 包名：`com.joe.jmlite`

## 1.1.8 本地修复

- 修复书籍信息、历史漫画详情、下载搜索全网漫画、最近下载、仓库图源五个页面预返回消失：进入生命周期改用 ValueAnimator，避免 `isEntering` 永久为 true。

- API 34+ 的 close 转场改为在 `super.finish()` 前设置；WebView 在 onCreate 预配置 close pop；登录打开浏览器后的来源页程序性关闭不播按钮动画、不消费预览栈。

## 1.1.5 更新

- 修复连续返回手势失效：此前在 `onBackInvoked` 同一帧内重注册回调，系统在结束本次手势时会再次清掉新回调。现在手势结束、取消后统一延迟 120ms 重注册，并在 `onStart`、`onResume`、窗口获得焦点时强制替换旧令牌。
- 修复返回后旧页面闪现：`PageMotion` 的 pop 视图动画默认在结束时回到 fillAfter=false，旧页会在被移除前恢复 alpha 1 并闪回一帧；现在 exit/enter 动画都设为 `fillAfter=true`，旧页保持淡出位置直到移除。
- 预览视图默认隐藏，仅在手势开始时显示；手势结束或取消立即隐藏，避免上一页快照在目标页下方重新浮现。
- 手势松手改为“整页移出屏幕”：保持缩小后尺寸，向右/向左移动 105% 屏幕宽度，不再中途透明度消失；目标页在移出结束后出现。
- 预返回灰度在松手瞬间直接归零，不再残留到动画结束；目标页视差同时优雅回正。
- 左右边缘识别增加 `BackEvent.getTouchX()` 校验，避免左返回被识别成右返回。
- 点击返回按钮与手势返回统一使用 pop 共享轴效果；所有 Activity 的关闭过渡统一配置，点击返回不触发预返回预览。
- 版本号提升到 1.1.5（versionCode 49），作为 1.1.4 的小版本修复发布。

## 1.1.4 更新

- 修复手势返回用一次就失效：每次手势结束后重新注册 `OnBackInvokedCallback`；恢复前台时仍强制注销旧令牌并注册新回调，避免部分设备在处理一次返回后丢弃回调。
- 继续修复从桌面返回后返回手势失效：`reinstall()` 在 `onResume`、窗口获得焦点和恢复 350ms 后执行；注销失败会被安全捕获，不会阻断新注册。
- 手势返回效果重做：松手时不再先把缩小页面恢复原尺寸；保持当前缩放，让页面向返回侧移动并淡出，目标页在淡出结束后出现。
- 预览图默认隐藏，只在预测性返回手势开始时显示，手势结束、取消或点击返回后立即隐藏，避免返回后上一页快照在目标页面下方重新浮现。
- 预返回视差：左侧右滑时目标页在预览中轻微左移，右侧左滑时轻微右移；松手后目标页优雅回到居中位置。
- 点击返回按钮统一为漫画详情的 pop 共享轴关闭效果；手势在子页面也使用相同的 Activity 关闭过渡。点击返回不触发预返回预览。
- 空书架/空书籍夹点击空白不再弹出添加菜单，右上角加号仍可用。
- 搜索图标静止状态不再设置裁剪区域；被打断的收起动画先取消再恢复 alpha/可见性；进入书籍夹主动结束搜索。
- 胶囊导航使用渐变半透明背景、半透明蓝色选中胶囊，点击无震动；书架/下载方向按视觉顺序计算。
- 版本号提升到 1.1.4（versionCode 48），作为 1.1.3 的小版本修复发布。

已在 MuMu 模拟器（Android 12）验证空书架点击、加号菜单、书籍夹导航隐藏、搜索展开/关闭后图标显示；预测性返回依赖 Android 13+，模拟器无法覆盖。

## 1.1.3 更新

- 再次修复从桌面返回后预测性返回失效：恢复前台时强制替换 `OnBackInvokedCallback`，不再依赖旧的注册令牌；注销失败会被安全捕获，并继续注册新回调。主页面在 `onResume`、窗口重新获得焦点和恢复 350ms 后各校正一次，子页面同步处理。
- 统一应用内部返回过渡：点击返回按钮与手势返回都使用同一套 pop 共享轴动画；手势松手时先结束预测预览、恢复页面原尺寸，再执行与按钮完全相同的返回过渡，不再叠加缩放回弹；手势返回子页面也使用和点击按钮相同的 Activity 关闭过渡，点击返回不触发预返回预览。
- 搜索图标：静止状态不再设置裁剪区域；被打断的收起动画会先取消再恢复 alpha/可见性；进入书籍夹时主动结束搜索，修复关闭搜索后图标透明但可点击的问题。
- 空书架/空书籍夹不再支持点击空白处弹出添加菜单；仍可通过右上角加号导入或创建书籍夹。
- 胶囊导航继续使用渐变半透明背景与半透明蓝色选中胶囊，保留连续滑动和按压缩放，点击不再触发震动。
- 书架/下载切换方向按导航栏视觉顺序计算，书架→下载时下载从右侧进入，下载→书架时书架从左侧进入。
- 优化交互：Tab 切换只保留新旧两个视图，取消时立即清理；搜索收起被打断时直接落定，避免重复动画和状态残留。
- 版本号提升到 1.1.3（versionCode 47），作为 1.1.2 的小版本修复发布。

## 1.1.2 更新

- 修复搜索图标消失：收起动画被打断时除了 alpha 还可能残留零宽/零高裁剪区域；现在静止状态不再设置裁剪，被打断的收起动画会先取消并恢复图标 alpha、可见性和完整布局，进入书籍夹及返回书架后都能正常显示。
- 修复回到桌面再打开应用后返回手势失效：窗口重新获得焦点和 Activity 恢复时重新注册预测性返回回调，并在 350ms 后再次校正，避免部分系统在后台丢弃回调后一直不恢复。
- 胶囊导航视觉优化：改为上下渐变的半透明胶囊、柔和描边和更轻的阴影，选中胶囊使用半透明蓝色；保留连续滑动和按压缩放，移除点击时的震动反馈。
- 修复书架与下载的切换方向相反：过渡方向改为按导航栏实际视觉位置计算。书架→下载时下载从右侧进入，下载→书架时书架从左侧进入；其他相近 Tab 同样按视觉顺序处理。
- 优化交互流畅性：Tab 过渡只保留旧页和新页两个视图，取消动画时立即清理中间视图；搜索栏收起被打断时直接落定静止状态，避免反复启动动画。
- 版本号提升到 1.1.2（versionCode 46），作为 1.1.1 的小版本修复发布；1.1.1 及更早支持 `version_code` 的版本都会收到更新。

## 图源网站与登录

仓库每个图源的收藏爱心左侧提供地球入口，打开该图源自身的首页，供浏览和登录使用。热门列表加载状态下方保留登录提示说明，搜索本图源时隐藏。明确返回登录要求时显示可点击的悬浮胶囊；超时、普通 403 和空列表不会被当成登录要求。从登录提示打开网站后也回到仓库，重新点击图源加载列表。浏览器与采用共享 Cookie 的图源共用登录状态；使用独立 API 令牌或扩展账号设置的图源仍取决于自身实现。

登录窗口没有底部导航栏，首页返回仓库，内页使用系统返回。右上角只有一个刷新图标：点击刷新当前网页，不会跳回图源首页，也不影响已打开的页面和返回栈。去广告规则固定开启，没有关闭开关，也不再提供“网址信息”菜单。

去广告内置用户指定的 [其他.prop 规则](https://ghfast.top/raw.githubusercontent.com/lingeringsound/adblock_auto/main/base/%E5%85%B6%E4%BB%96.prop)，快照版本 `20261104121737`。实现标准 CSS 元素隐藏和常用 ABP 网络规则，包括站点范围、资源类型、第三方限制及白名单；不执行规则中的脚本注入，不支持的修饰符和程序式选择器会跳过。规则仅作用于内置网页，不修改图源 API、搜索或阅读请求；当前随应用更新，不后台自动更新。

## 构建

需要 JDK 21、Android SDK platform `37.2`、Build Tools `37`，首次构建需要网络下载 Gradle 和 Maven 依赖。

```powershell
.\build-mihon.ps1 -JavaHome C:\path\to\jdk21 -AndroidHome C:\path\to\android-sdk
```

输出位于 `build/`。项目不发布签名私钥、签名密码或本机工具链。构建脚本在没有本地密钥时会生成自己的签名；这种签名不能覆盖安装官方发布包。发布维护者须妥善保留原签名。

应用源码位于 `app/src/main/`，Mihon 适配工程位于 `mihon/`。当前 JVM 逻辑测试位于 `mihon/app/src/test/`；`tests/java/` 和 `build-legacy-tests.ps1` 为旧测试，不作为当前验证结果。每版实际构建、测试和设备验证边界以该版 Release 随附验证说明为准。

## 发布后如何触发更新

1. 提升应用版本名及 `versionCode`，例如 `3.8.0` → `3.8.1`，并用相同发布密钥签名。
2. 在本仓库创建对应 GitHub Release，使用可比较的标签，例如 `v3.7.2`，填写更新说明，同时上传 APK 和构建脚本生成的 `build/update.json`。公开 APK 名称须与元数据中的 `JianYue-版本-arm64-v8a.apk` 一致。
3. 将它发布为最新正式版。草稿和预发布不用于正式版更新提示；Release 正文会显示在应用更新弹窗里。
4. 已安装支持更新检查版本的手机在下次打开应用时检查版本。仅推送源码、创建空标签或上传到其他仓库不会触发更新。

检查更新需要手机能访问 GitHub。3.7.0 起优先读取最新正式 Release 附带的更新元数据，减少对匿名 API 配额的依赖；元数据缺失或无效时回退 API。每次打开检查一次，主元数据通道失败时尝试API；限流时遵守服务器要求。应用不自动下载或安装 APK。尚未含有此功能的 3.1.0 需要先手动安装 3.3.0 或更高版本。
